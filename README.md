# 10x AI Growth Marketing Kit

**A growing AI Marketing Skill Kit for everyone who wants to grow with AI.**

**唔係再收集 Prompts，而係將你做 Marketing 嘅判斷，寫成 AI 可以重複執行嘅 Skills。**

好多 Marketer 已經識叫 AI 寫 Post、做 Research、砌 Campaign。

但真正開始工作，就會遇到幾個問題：

- 每次開新對話，都要重新解釋公司、客戶同品牌；
- AI 未做 Research，就已經急住交答案；
- Campaign 睇落好完整，但受眾、Offer、CTA 同 KPI 都係估出嚟；
- 同一段文案改少少，就當成 Threads、LinkedIn、Facebook 同 Instagram；
- Draft 好似寫完，但冇人知道根據乜嘢驗收，亦唔知下一步交俾邊個。

所以我整咗呢套 **10x AI Growth Marketing Kit**。

目前有十個可以安裝、閱讀、測試同修改嘅 AI Marketing Skills，將 chatroom business memory、Audience Think & Check、內容研究、SEO／GEO 內容、社交文案、Reference Style／Tone／Skill 拆解、Instagram Carousel、AI 圖像製作、香港 Threads、Sales Funnel Landing Page，串成一條有來源、有判斷、有交接、有 Human Review 嘅工作流。

十個 Skills 只係起點。我哋會按照真實 Marketing 工作持續測試、改善同加入更多 Skills，令呢個 Kit 同每一個想用 AI 成長嘅人一齊成長。

## 我點解會寫呢套 Skills？

我一路由 Designer、Marketer、Growth Marketer，做到而家嘅 AI Growth Builder。

實際做 Marketing 時，我發現 AI 最容易令人誤會嘅地方，唔係佢「唔識做」，而係佢太快交到一份睇落似完成嘅答案。

一份文案可以句句通順，但冇真正觀點；一份 Campaign Plan 可以有晒 Funnel、Channel 同 KPI，但入面一半資料從來冇人確認；一篇 SEO 文章可以有齊關鍵字，但冇一個重要 Claim 有可靠來源。

問題通常唔係欠一條更長嘅 Prompt。

問題係我哋未將自己平時做決定嘅方法講清楚：

- 開始之前要睇乜；
- 資料不足時應該問乜；
- 邊啲係事實，邊啲只係判斷；
- 工作應該按照甚麼次序進行；
- 交付要包含甚麼；
- 去到邊一步一定要人拍板。

我寫 Skill，就係想將呢啲平時收埋喺腦入面嘅工作判斷，變成團隊同 AI 都可以理解、重複同改善嘅方法。

> AI 工具可能幾個月就轉一次，但你點樣 Research、判斷、交接同驗收，先係真正可以累積嘅能力。

## Skill 唔係一條「超級 Prompt」

一條 Prompt 通常只係話俾 AI 知「今次想做乜」。

一個 Skill 就係將「呢類工作應該點樣做」寫成一套可重複使用嘅工作方法。

| 一般 Prompt | 一個完整 Skill |
| --- | --- |
| 一次性指令 | 可以重複安裝及使用 |
| 依賴今次對話有冇講清楚 | 先檢查需要嘅 Context |
| AI 可以直接估缺失資料 | 清楚標示已知、假設及缺口 |
| 每次輸出格式都可能唔同 | 有固定 Output Contract |
| 好難交俾另一個人繼續 | 有明確 Handoff |
| 覺得「寫得幾好」就算完成 | 有 Quality Gate 同測試準則 |

一個實用 Skill，通常至少包含：

1. **Trigger**：甚麼情況應該啟動；
2. **Required Context**：開始前需要讀取甚麼；
3. **Questions**：缺少關鍵資料時點樣問；
4. **Workflow**：工作次序；
5. **Output Contract**：交付格式；
6. **Guardrails**：不可以越過嘅界線；
7. **Quality Gate**：完成前點樣驗收；
8. **Handoff**：下一步交俾邊個 Skill 或人。

## 點解一個 Skill 要有咁多規限？

因為 AI 最危險嘅唔一定係完全答錯，而係用好多合理文字，將未確認嘅嘢包裝成好似已經決定。

| Skill 入面嘅規限 | 實際解決嘅問題 |
| --- | --- |
| Trigger | 防止用錯 Skill 處理任務 |
| Required Context | 防止未了解公司就開始生成 |
| Status | 分開已確認、假設、缺口及阻塞 |
| Questions | 補回真正影響結果嘅資料 |
| Workflow | 保留正確思考及執行次序 |
| Output Contract | 令結果可以直接驗收及交接 |
| Guardrails | 防止虛構、越權或未批准發布 |
| Quality Gate | 定義甚麼先叫真正完成 |
| Evals／Test Cases | 檢查修改 Skill 後有冇整壞原有行為 |

> 規限唔係為咗限制創意，而係令創意可以被驗收、重複同交接。

## 呢套 Kit 背後嘅工作方法

我將 Marketing 工作拆成五層：

```text
Company Context
      ↓
Research Evidence
      ↓
Strategic Decision
      ↓
Content Production
      ↓
Human Review
```

核心原則係：

### 1. Context before creation

未了解公司、客戶、Offer 同目標之前，唔應該急住生成內容。

### 2. Evidence before opinion

先讀真正 Sources、客戶語言同市場訊號，再決定我哋有甚麼值得講。

### 3. Strategy before production

唔係一開始就問「出咩 Post」，而係先確認想改變邊一類受眾、推動甚麼行動，同內容位於 Funnel 邊一層。

### 4. Human judgment before publishing

AI 可以研究、整理、挑戰、建議同起 Draft；事實、品牌立場、客戶資料、預算及正式發布，仍然要由人審批。

### 1. Social Content Research／社交內容研究

`預計 10–30 分鐘`

👤 **你只需要提供：** YouTube、Instagram、Facebook、Threads、LinkedIn、X 連結，或者影片、截圖、Caption、逐字稿。

#### 點解我會寫呢個 Skill？

做 Content 最常見嘅錯誤，唔係冇 Idea，而係太早開始寫。

我哋見到一條熱門內容，好容易直接叫 AI「幫我整三條類似嘅」。但如果 AI 根本睇唔到 Carousel 圖片、只讀到搜尋摘要，或者將創作者觀點當成已核實事實，最後只會變成憑印象抄橋。

呢個 Skill 第一件事唔係分析，而係交代自己實際讀到幾多：

- `FULL`：正文及主要媒體已讀；
- `PARTIAL`：只讀到部分內容；
- `IMAGE_ONLY`：只有圖片或截圖；
- `BLOCKED`：內容無法存取。

#### 工作流程

```text
提供內容
→ 確認讀取範圍
→ 提取實際證據
→ 分開 Evidence 與 Interpretation
→ 分析 Hook、結構、Proof 同 CTA
→ 檢查風險
→ 發展原創 Content Angles
```

讀取方法可以包括瀏覽器、官方字幕、逐字稿、OCR；影片冇字幕時，先考慮用 Whisper 轉錄，FFmpeg 可以協助抽音訊或整理媒體。呢啲只係取證方法，唔代表每一個平台、私人內容或受限制影片都一定讀得到。

#### 主要輸出

- Access state；
- 實際讀到嘅內容；
- 一句總結；
- Hook 與結構分析；
- 值得參考嘅機制；
- 風險或盲點；
- 三個重新發展嘅原創角度。

### 2. SEO + GEO Blog Writing／搜尋及 AI 引用內容

`預計 45–90 分鐘`

👤 **你只需要提供：** 題目或搜尋問題、目標客戶、地區、內容目標、可用來源、公司資料及 CTA。

#### 點解我會寫呢個 Skill？

SEO／GEO 唔應該由「幫我加多啲 Keywords」開始。

應該先理解搜尋者真正想了解、比較、解決定購買甚麼，再判斷公司有冇足夠資料同資格回答。

呢個 Skill 會將重要 Claim 分成：

- `VERIFIED`：已有可靠來源核實；
- `PROVIDED`：由用戶提供但未獨立核實；
- `COMPANY_FRAMEWORK`：由 Company Brain 支持嘅公司方法或 decision rule；
- `INFERENCE`：根據證據作出嘅判斷；
- `SOURCE_NEEDED`：未補來源前不可當成公開事實。

#### 工作流程

```text
Source Guide → Human Review
→ SEO Title → Human Review
→ Article + Meta + CTA + Link Ledger → Human Review
→ Local HTML → Human Review
```

SEO 同 GEO 共用同一個底層：內容要準確、具體、有來源、結構清楚，而且真係幫讀者完成一個決定。公開文章不會顯示研究來源、URL 或引用清單；provenance 會留在內部 Source Guide 同 Claim Notes。每次只完成一個階段，唔會一收到 Source 就直接跳到 HTML 或發布。

如有公司資料，AI 必須先讀 Company profile 同 Current Offer；只有公司名並不足夠。CTA、站內連結同直接目的地要逐條確認，欠資料時使用 `CTA_TBC` 或 `LINK_TBC`。Source 圖片授權未確認時，只可放入本機 HTML 作 `INTERNAL_REVIEW_ONLY`，不當成已批准發布資產。

寫作層會使用 DotAI-derived practical-operator style：先講讀者真正遇到嘅工作阻力，再將技術翻譯成 input、output、時間、成本、風險、審批同下一步。每個重要例子要有具體 deliverable 及 human boundary；長文會建立可獨立理解嘅 Owned Answer Units，而唔係用 generic advice 加幾次品牌名。若 Company Brain 已提供獲批准 Brand Voice，會以該 Voice 為準。

平台輸出亦唔只係正文：包括 H1、Meta title、Meta description、slug、Reader Link／CTA Ledger、internal-link plan、supported FAQ／Schema recommendation，以及需要時分開記錄 Discovery、Selection、Absorption、Attribution、Accuracy、Stability 同 Action 嘅 GEO monitoring plan。

#### 主要輸出

- Source Guide 及 Claim Notes；
- SEO Title and Angle；
- Article、Meta、CTA 及 Reader Link Ledger；
- Owned Answer Units、supported FAQ／Schema 及 internal-link plan；
- 本機通用 HTML Review（按要求）；
- Phase Receipt、QA Status and Open Items。

### 3. Social Post Writing／平台原生社交文案

`預計 10–20 分鐘`

👤 **你只需要提供：** 一個已核實 Source、Idea、Campaign Handoff 或觀點，再加 Audience、Voice、平台同 CTA。

#### 點解我會寫呢個 Skill？

同一個 Insight 可以去唔同平台，但唔應該將同一段文字 Copy and Paste 四次。

Threads、LinkedIn、Facebook 同 Instagram 嘅閱讀情境、節奏、Context 同 CTA 都唔同。真正應該保留嘅係同一個核心觀點，而唔係同一個句式。

呢個 Skill 使用一個簡單原則：

> **One Post, One Job, One Point.**

每篇 Post 先揀一個主要工作：

- Teach；
- Build trust；
- Start conversation；
- Announce；
- Drive action。

#### 工作流程

```text
讀取可靠內容
→ 選擇 Audience 同 Voice
→ 鎖定 One Job、One Point
→ 選擇內容 Shape
→ 撰寫 Source Version
→ 按平台重新設計 Hook、節奏同 CTA
→ Fact／Voice／Platform QA
→ 輸出 Draft Pack
```

Founder、Company 同 Neutral Expert Voice 亦會分開處理。AI 不可以為咗增加故事感，代你虛構失敗、客戶、對話或個人經歷。

#### 主要輸出

- Decision Header；
- Threads Draft；
- LinkedIn Draft；
- Facebook Draft；
- Instagram Caption Draft；
- CTA options；
- Assumptions and source notes；
- Status: `DRAFT`。

### 4. Sales Funnel Landing Page Builder／銷售漏斗頁面

`預計 45–120 分鐘；Operations 視乎連接範圍`

👤 **你只需要提供：** Offer、目標客戶、Proof、主要 CTA、Design MD／reference，以及表格同資料用途。

#### 點解我會寫呢個 Skill？

Landing Page 最常見問題唔係「唔夠靚」，而係 AI 太快揀咗一種 generic style、未鎖定 Offer 同 CTA 就開始砌頁；表格睇似成功，亦未必真係寫入 Google Sheet、發到確認信或保留 UTM。

呢個 Skill 將 Copy、Design、Build 同 Lead Operations 分開驗收。Standard V1 鎖定一個 Offer、一個 CTA、一個短表格同一個 next step；Quiz、scorecard 同動態 Assessment Results 留俾另一個 Advanced Skill。

#### 工作流程

```text
Offer Brief
→ Style Review
→ Copy Review
→ Build
→ UTM Tracking
→ Lead Operations
→ Desktop／Mobile QA
→ Human Review／Controlled Release
```

頁面視覺或 interaction 有修改時，必須使用 `design-taste-frontend` 同 `emil-design-eng`，並建立 portable design receipt。CRM／email／reminder 在範圍內時，另外使用 operations receipt 同 destination read-back；Local preview 或 HTTP success 不會當成完整 Lead journey。

#### 主要輸出

- Landing Page Brief；
- Style direction／reference mapping；
- Section-by-section Copy Deck；
- Page source／CMS handoff；
- `utm-registry.csv`；
- Design receipt、Operations receipt、Desktop／Mobile evidence；
- Release status 同下一個 Human approval。

### 5. HK Threads Writer／香港 Threads 文案

`預計 5–20 分鐘`

👤 **你只需要提供：** Source、新聞、觀點、故事、工作紀錄或已有 Draft。

#### 點解我會寫呢個 Skill？

Threads 唔係將長文刪到 500 字，亦唔係每句斬開一行就叫有呼吸感。內容要先有一個值得講嘅判斷，再按證據揀 Hot Take、Reaction、Personal Story、Build Note、Review、Anti-pattern、Curated List 或 How-to。

Skill 會分開處理 Hook 強度同 Claim 強度：L3 可以更尖銳，但唔可以新增數字、因果、引句或保證。`complete-single-500`、`notes-link-reply` 同 `staircase-thread` 三種模式都會保留手機閱讀節奏，並對每個可發布 Segment 使用 Python `len(text)` 計數。

#### 主要輸出

- 自然香港廣東話 Threads Draft；
- Content Job、Hook Level 同 Format Mode；
- Ordered root／replies；
- 每段 Python count；
- Unverified items、Claim boundary 同 `publication_status: draft`。

### 6. Instagram Carousel Studio／Instagram Carousel

`預計 45–120 分鐘`

👤 **你只需要提供：** Source／Brief、Audience、One Message、你自己嘅見解、CTA，同可選參考圖。

呢個 Skill 會先鎖定「寫俾邊個、點解佢要理、你比 Source 多咗乜嘢判斷」，再將一個重點寫成預設 10 張嘅完整故事。唔使揀 Style，亦冇 HTML；完整內容經 Human Review 後，直接交俾 AI 圖像 Skill。

#### 主要輸出

- Audience-specific angle、Creator Judgment 同 10-card story；

### 一個香港 SME 示範情境

以下只係教學流程，唔係真實客戶成效：

假設一間香港中小企準備推出「AI 工作流程培訓」。

1. 用 `social-content-research` 研究市場上相關影片、貼文同客戶討論，分開證據、觀點同可發展角度；
2. 由負責人確認主要受眾、Offer、核心訊息、CTA、渠道同轉化路徑；
3. 將需要建立搜尋信任嘅題目交俾 `seo-geo-content`，Human Review 後輸出 Blog handoff；
4. 將已確認 Offer、Proof 同 CTA 交俾 `sales-funnel-landing-page-builder`，完成文案、設計、UTM、Lead journey 同 Landing handoff；
5. 將已確認 Landing Page 同 Blog 交返網站 Project，直接用自然語言要求整合，由現況續做、組合 routes、完成 Preview，同等候 Production approval；
6. 將 Campaign 觀點同活動訊息交俾 `social-post-writing`，分別製作平台原生 Draft；
7. 用 `mira-audience-qa` 代入目標客戶，檢查對方是否理解、覺得相關、信任內容，同知道下一步；修正後再 Recheck。
8. 由負責人核實 Claims、品牌語氣、活動資料、CTA、data behaviour 同 Preview，再決定正式發布。
9. 用 `save-to-vault` 將已確認決定、artifact evidence 同具體 feedback 路由到 Company Vault；brainstorm、superseded versions 同敏感資料唔入 canonical knowledge。

真正嘅價值唔係「一次過生成好多 Content」，而係每一步都知道資料從邊度嚟、點解咁決定、下一步交俾邊個。

## 唔好只學識「用」Skill

我想用呢個 Repository 教嘅，唔係叫大家複製 Jimmy 嘅答案。

真正目標係學識將自己做事嘅判斷寫成 Skill。

你可以用以下練習：

1. 揀一個真實 Marketing 任務；
2. 用原版 Skill 跑一次；

4. 打開 `SKILL.md`、`references/` 或 `assets/`，找出控制呢個結果嘅規則；

你要問嘅唔係：

> 「點樣令 AI 寫得再靚啲？」

而係：

> 「我自己平時根據甚麼資料作判斷？邊個步驟唔可以跳過？甚麼結果先算合格？」

當你答到呢三條問題，就已經開始由 AI User 變成 AI Builder。

## 安全及 Human Review 界線

呢套 Skills 會保留以下共通原則：

- 資料不足時標示缺口，不虛構公司、客戶、合作、價格、數字、結果或個人經歷；
- `Draft` 不等於 `Approved`；
- `Approved` 不等於 `Published`；
- 不會自動發佈、發送訊息、花廣告預算或處理客戶個人資料；
- 涉及時效性資料、法規、產品功能、外部 Claim 或第三方內容時，需要核實當前來源；
- AI 可以提出建議，但品牌立場、公開承諾、客戶資料及最終發布由人負責。
