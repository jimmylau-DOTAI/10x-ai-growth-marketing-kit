# 產品／服務詳情：先規劃，再出圖

只在產品詳情頁、服務介紹頁或多屏 Offer 介紹任務讀本檔。單張海報沿用 image-plan 的主張與構圖，不硬加整套詳情流程。

## 1. 先排完整購買問題

生成前，在同一份 plan 列出整套頁序。每屏寫：**購買問題 → 一句回答／主標題 → 可用產品證據 → 主要畫面**。用戶看到的是簡短表格，不用填表。先看結構是否完整、是否重複，才寫各屏 prompt。

以下是可選模組，不是八屏固定模板；按用戶張數、產品／服務特性、購買阻力與證據刪減或重排。服務可用「服務定位、客戶情境、方法／流程、交付物／證據、方案／FAQ／CTA」五段，不能硬套材質、尺寸或開蓋流程：

| 模組 | 解答的問題 | 畫面及資料條件 |
| --- | --- | --- |
| 產品認知 | 這是甚麼、適合誰？ | 真包裝／主體與最必要名稱；第一眼能辨認商品 |
| 使用需求／合理預期 | 它針對甚麼需要、能期待甚麼？ | 已提供用途與場景；不捏造問題嚴重程度或效果 |
| 包裝信息 | 是哪一款、標籤寫甚麼？ | 真實可見正面／標籤；不可用 AI 小字作規格證據 |
| 質地／材質／形態 | 實物看起來如何？ | 有來源的特寫；包裝相不等於內部質地證據 |
| 取用步驟 | 如何打開、取出或準備？ | 正確包裝結構與已確認操作；無背面／開蓋證據不亂畫 |
| 使用流程 | 實際怎樣使用？ | 來源支持的動作與順序；不新增用量、路徑或頻率 |
| 規格／收納 | 尺寸容量合適嗎、如何保存？ | 已核實數值與保存資訊；不為湊頁數編造 |
| 購買／使用前確認 | 有甚麼需要先確認？ | 有來源的適用限制、注意事項或版本選擇 |

一屏可有多個支援同一回答的元素；不能把互不相干的賣點、用法、规格塞在同一屏。用戶只要兩張詳情圖，就選最重要的兩個問題；其餘可省略，不擅自擴成八張。若需求真的超出張數，先提出取捨。

## 2. 讓產品或服務融入海報

先讀 source-and-style 的品牌／包裝資料，再在 plan 寫出色彩角色及融合做法：

- **商品品牌：**從用戶提供的品牌宣傳圖觀察它慣用的主色、字體氣質、攝影光線、形狀語言及資訊層級；沒有官方核實就稱「提供的品牌參考」，不聲稱最新官方規範。
- **實際 SKU：**以今次真包裝的主色、版本標示色、材質及造型為準。同品牌不同顏色／容量的參考只能借視覺語言，不能換掉正在售賣的商品。
- **公司／店舖識別：**加入真 Logo 與硬性品牌規則。兩個品牌共存時明確主次；背景色可配合商品，不能擅自為求統一而改 Logo 或包裝顏色。
- **色彩安排：**定義主背景、次背景、文字、功能區及點綴色；用明暗與冷暖差拉開產品和背景，不能只把整張染成包裝主色。先交代由哪個來源推導，不杜撰正式色碼。
- **畫面融合：**讓產品、場景與圖示共享合理的光源方向、色溫、透視、接觸陰影與清晰度。檢查去背白邊、漂浮感、比例及地面接點，避免像白底商品圖貼在另一張海報。
- **保留商品真實性：**可調整周圍場景、光影與構圖來融合；不能重畫標籤、改變真實包裝色相、結構或容量。原相角度不足以支持構圖就換構圖或索取素材。

## 3. 借用設計，不借用證據

參考的功能示意可啟發解說方式，但不證明今次商品的機理或功效。科學箭嘴、粒子、微觀截面、測試標示、比較表及前後效果圖，都要有相應來源；概念示意須講清是示意，也不可藉此畫出未證實機理。借用清楚的層次和閱讀順序，不照搬細小難讀的文字、無來源數據或其他 SKU 的標章。

## 4. 整套驗收

Quick Batch 先用代表圖驗產品 Form Lock 或服務 Truth Lock、真 Logo、claim boundary 與海報融合，通過就連續生成；成套後一次檢查頁序、重複、同款商品或同一服務範圍、色彩角色和字體層級。Review First 才先交代表圖等確認。Final QA 才按 native-images 逐張跑完整尺寸與版本驗收。任何模式都不能把產品跑樣、錯誤用法、捏造服務流程或假案例當成風格問題放行。
