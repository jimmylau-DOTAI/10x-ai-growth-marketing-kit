# 把產品資料變成具體設計

這份規則適用詳情圖片／廣告製作；不用學生交額外文件。相關事實回讀產品知識與來源，品牌和参考按 source-and-style，原有逐頁欄位按 pdp-blueprint。

## 先有三個不同的說服角度
在同一 job 的 06-creative-plan.md 記三個方向，每個只需：買家問題、受支持的產品回答、主標、主畫面／拍攝視角、為何適合產品、不可寫的內容。至少改變購買動機和畫面敘事，不只是換配色。沒有三個獨立賣點，可以用同一事實對應不同真實情境，明示這是場景變化。
AI 推薦一個；不要要求新手回答抽象的「想要甚麼美感」。三方向是短文案預案，不是先生成三套圖。

## 一份可重用的視覺決定
在 06-creative-plan.md 用實際 reference 說明：
- 背景、文字、點綴色的角色；包裝本色與公司 Logo 的保留方式。估算色碼不當正式品牌規範。
- 商品在畫面多大、位於哪裏，光源從哪裏來、如何接地；文字放在甚麼安靜區域。
- 主標／說明／標籤的層級、留白、Logo 安全區、畫面希望傳達的情緒。
- 哪些頁用生活照、哪些用特寫、步驟或規格資訊；用途與 evidence 決定形式。概念圖不能冒充微觀測試／真實效果。
- 對照 reference：保留哪三個設計特徵，為配合本品改哪兩點，禁止搬走哪些他牌元素。
沒有 reference 且用戶已授權自行設計，明示 candidate，從產品與用途建立上述具體決定。不要虛构看過的設計或「高轉化」證據。

## 每張圖有一個資訊任務
生成前於同一計劃記：content_id／版本、圖片用途、買家問題、來源 ID、精確圖內文字、構圖、原素材相對路徑、人物／場景差異、預期視覺檢查點。
廣告先讓人認產品與一個動機：一個主標、必要的短說明、合用才加 CTA。詳情圖則用標籤、特寫或步驟解釋該頁問題；資訊量來自解答清楚，不是堆字。
手機預覽若讀不清，先刪重複句與低優先資料，重新構圖；不能縮到小字去塞滿。缺來源時省掉該數字／承諾，讓受支持的外觀、容量、動作或場景負責說明。

## 一張校準，再按模式延伸
一般先 Page 01；僅廣告就先主方向廣告。Quick Batch 將代表圖當內部校準，通過產品、Logo、claim 三項硬檢後直接延伸已選套裝；Review First 才把代表圖交用戶確認後再做。詳情＋廣告可共用視覺語言，但廣告必須重做單訊息構圖，不能把詳情頁縮小代替。
用戶說「唔靚」時，先對照原圖和 reference 找出焦點、光影、字量、色彩／品牌哪項不合，提出具體改法；不要重新索取全部資料或只加「更漂亮」到 prompt。按 native-images 的重試與驗收範圍執行。

## 讓下次出圖有資料可依
在 06-creative-plan.md 維護素材索引：content_id、angle_id／page_id、版本、使用來源、產品原圖／Logo／reference、圖內及配套文案、實際輸出路徑、AI QA、人確認範圍。
未生成記 not_generated，不放不存在的連結。Quick Batch 只需一份 batch manifest；Final QA 才為每張成品保留 request／delivery。修改新增版本；原始來源、候選、已確認風格和被拒版本都能分辨。後續每張仍要帶真產品、真 Logo 及合用參考，不能只依賴上一張生成圖。
資料存於目前 outputs/<job>/，不自動升格為正式公司品牌規則。接數據時可以沿 content_id 對應真 ad_id，但本 Skill 不自行投放或建立 CRM。
