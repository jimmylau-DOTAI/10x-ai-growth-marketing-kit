# 先做全套文字藍圖，圖像是另一個明確階段
「只做藍圖／不要生成圖片」是文字終點：輸出完整 05-offer-detail-blueprint.md 後停；即使上文有一次過要求，本次更具體的 blueprint-only 優先。不能自動出 Page 01。

## 數量、格式和語言
只有「幫我做詳情圖」而沒張數時，沿 SKILL.md 的預設批次大小及證據範圍直接規劃，不新增數量審批。預設 5 張 Core Detail Pages：產品是產品認知、核心選購理由、實物細節／質地、實際用法、規格／買前問題與 CTA；服務是服務定位、客戶情境、方法／流程、交付／證據、方案／FAQ／CTA。每張仍只圍繞一個主問題，但不能只用一個 headline 敷衍：一頁要有 headline、短 body、3–4 個受支持的資訊模組、閱讀順序和版式安排。用戶只指定 Page 01 時只做該頁。七類圖片覆蓋不是七頁定額。
明確要求 Shopify 十頁時，以下十個章節完整保留，預設建議 16:9、自然英文 headline/subheadline（僅此已指定方案）。其他任務跟已確認張數、直／橫版和市場；「5 張直版繁中詳情圖」就是 5 張，不硬改十頁英文。比例不是官方平台合規承諾，待實際版位／手機閱讀驗證。

### 5 頁 Core Detail Page 序

| Page | Section | 應解答的問題 | 每頁必要內容層次 |
| --- | --- | --- | --- |
| 01 | Product Recognition | 這是甚麼、第一眼怎樣認得？ | Hero、產品名稱／版本、短 body、3 個事實模組、第一個 CTA |
| 02 | Core Evidence | 核心食材／材料／結構是甚麼？ | Headline、解釋段、3–4 個證據模組、局部細節圖、買家意義 |
| 03 | Texture / Detail | 實物細節或質地到底是怎樣？ | Headline、可見描述、detail callout、局部大圖、邊界提示 |
| 04 | How It Is Used | 真實怎樣準備或使用？ | 清楚步驟、每步短句、可行動作圖、不可自行推演的提示 |
| 05 | Format / Before You Buy | 一盒有甚麼、買前應核對甚麼？ | 產品格式／已核實規格、三點核對、FAQ 式短答、中性 CTA |
一頁處理一個購買問題；ten pages 不是一張十格海報。若需要研究先按 customer-insights 補齊已授權範圍，無來源之內容標 TBC 而非填效果保證。

### 服務 5 頁 Core Detail Page 序

| Page | Section | 應解答的問題 | 每頁必要內容層次 |
| --- | --- | --- |
| 01 | Service Positioning | 這項服務是甚麼、為誰而設？ | Hero、服務名稱、短 body、3 個範圍模組、第一個 CTA |
| 02 | Customer Context | 客戶通常面對甚麼情境？ | Headline、理性情境描述、3–4 個已支持問題模組、不可恐嚇或假痛點 |
| 03 | Method / Process | 實際怎樣進行？ | Headline、清楚流程、每步短句、真實接觸點、不能憑空添加步驟 |
| 04 | Delivery / Evidence | 會收到甚麼、如何知道進度？ | 已核對交付物、可見工作細節、邊界提示；無證據不畫假 dashboard、case 或數字 |
| 05 | Options / FAQ / CTA | 怎樣判斷合適、下一步怎樣做？ | 已核對方案或準備事項、FAQ 式短答、中性 CTA |

混合方案每頁要標清是產品、服務或兩者的哪一部分；不可讓服務承諾偽裝成產品功能，或反過來。

## 長詳情頁十頁序
| Page | Section | 應解答的問題 |
| --- | --- | --- |
| 01 | Hero / First Impression | 是甚麼、適合誰？ |
| 02 | Problem / Pain Point | 哪個真實日常困擾？ |
| 03 | Offer Solution | 產品已確認的特點或服務已確認的方法如何回應它？ |
| 04 | Key Benefits | 為何這些特點值得在意？ |
| 05 | How It Works | 正確怎樣使用或參與？ |
| 06 | Material / Detail / Delivery | 實物細節或交付內容是甚麼？ |
| 07 | Fit / Compatibility / Eligibility | 規格、適用條件或服務資格合適嗎？ |
| 08 | Lifestyle / Service Use Case | 在我的生活／工作怎樣使用或接觸？ |
| 09 | FAQ / Safety / Trust | 買前與使用前要確認甚麼？ |
| 10 | Final CTA / Offer Close | 下一步可以做甚麼？ |

每頁按 [image-storyboard.md](image-storyboard.md) 的製作卡完整寫入本藍圖，不只列章節標題。包含實際文案、購買問題、證據、構圖、產品角度、原素材、reference、角色變化及禁止內容；不另開逐頁文件。labels 數量按本頁資訊需要，不強迫湊齊。
另附 Q-ID → F-ID → C-ID／R-ID 對應（不適用可空並說明），以便核對本頁為何存在。編排頁碼與優先級可以不同：要解釋敘事次序如何回應優先客戶問題。

## 資料不足時有用地完成
文字藍圖沒有圖片 reference／Logo 時，可以根據已有品牌描述提出標明 candidate 的視覺方向，列出出圖前真正需要的素材，繼續完成可做的頁序與文案；不要求學生補完全部素材才分析。不得把候選方向寫成已確認品牌設計。
沒有材質成分：展示原相可見表面／縫線／包裝，不能寫醫療級／環保／防水。
沒有精確尺寸：Page 07 改成選購前核對清單、已知容量／重量與適用限制；不可畫未確認尺規。
沒有證據的效能：Page 04 使用受支持產品特點或已知用法，不編數據。
沒有優惠：Page 10 中性 CTA（例如 View product details），不造倒數或價格。
labels 沒有足夠證據便減少或省略，在內部藍圖寫缺口／待確認，不把 TBC 假裝正式顧客 copy。

把「給買家看的文案」與「AI 給製作人的資料缺口」分開。不要把「本次資料未確認材質」「防滑性能仍需確認」「缺照片」直接變成海報主標／chips；通常改以已確認的細節或選購問題寫自然文案，把尚缺證據留在本頁 production note。若買家必須知道適用限制，保留清楚的事實性提示／購買前查詢方向，但不以未知來暗示通過測試。資料只夠少數真正不同的重點時，指出哪些十頁內容有重複風險及可合併建議，同時保留用戶指定十頁藍圖；不能靠虛构新 benefits 湊數。

## 統一視覺規範與兩個 Lock
結尾必交：
- 全套視覺：來源推導配色（背景、主體分離、文字、點綴）、字體氣質與層級、文字密度、留白、Logo 位置／clear space、callout、光線與質感。主題跟產品包裝呼應，保留公司識別。
- Product Consistency Lock：產品任務必交同 SKU、形狀、結構、顏色、包裝／Logo、比例、已確認細節；原圖優先於 Sheet；推演區不得當真；列出每次工具須帶的真資產。
- Service Truth Lock：服務任務必交同一服務範圍、對象、方法、流程、交付物、已證實案例／成果與限制；不可製造客戶 Logo、testimonial、證書、數字、dashboard 或 before-after。列出每次工具須帶的真實服務來源。
- Brand Consistency Lock：真公司 Logo、品牌色／字體氣質、文字語氣、排版系統；情境可多元，但不能十頁十套品牌。
- Variation plan：角色、背景、視角與光影情緒對應不同頁面；同一個操作連續圖可同人同景。不得每頁重複相同 model 或房間模板。
- 下一步依當前模式：只要藍圖交文字後停；Review First 先生成 Page 01 後等方向；已授權 Quick Batch 則完成所要求批次。不能因藍圖結尾有 Page 01 就擴大單頁要求。
