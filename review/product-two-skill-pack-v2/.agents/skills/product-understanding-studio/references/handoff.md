# 精簡交接

新工作只需一份 `offer-notes.md`（舊 `product-notes.md` 可用）、`images/` 下五張理解圖，以及 `sources/` 下真正需要的原素材。不額外建立品牌摘要、研究報告、案例表、manifest 和 handoff 多份同內容文件。

交接時不是只寫「下一步做詳情圖」。AI 必須真的載入 `brand-image-studio/SKILL.md`，再讀 `product-intake.md`、`product-detail.md` 和 `pdp-blueprint.md`；完成 5 張理解圖不等於已進入第二個 Skill。第二個 Skill 先交 5 頁 Core Detail Page（產品 PDP 或服務介紹頁）的完整可排版文案，才可生成圖片。

正常接手條件：指定網站及其他網站的研究已記錄、文案素材已展示、五張圖已生成並核對產品身份／來源。多角度與質地須記實際覆蓋及未確認部分。未完成就記 partial 和具體缺口，不自動把純筆記當整包交第二個 Skill；用戶明確要文字交接或先跳過時，記清例外即可，不重問已批准事項。

筆記的交接部分保留：Offer 類型、SKU／版本或服務方案、來源及事實、文案素材、客戶疑問、Product Form Lock 或 Service Truth Lock、限制、五圖計劃、實際圖片路徑和狀態、原圖／服務證據／Logo／reference 路徑、已答市場與成果需求、用戶修正。生成圖不是事實依據；產品原圖或服務來源必須隨下游出圖重新提供。

若既有工作已有 02-product-knowledge.md、source-receipt.md、product-handoff.md 或等效服務資料，直接讀其有效內容即可，不必重做或搬動歷史資料。新輸出集中到 offer-notes.md。

第二個 Skill 直接讀筆記與實際資產，不要求十個案例、三張使用圖或另一張額外總覽。用戶指定只要文字時註明未生成圖片；不存在檔案就標 missing，不預填假路徑。

交付狀態用 generated / needs_revision / not_generated 等實際結果；確認另記用戶原話和範圍。只說「好看」不等於核實包裝、數值或效果。換 SKU／結構影響的圖與文案才重新檢查。
