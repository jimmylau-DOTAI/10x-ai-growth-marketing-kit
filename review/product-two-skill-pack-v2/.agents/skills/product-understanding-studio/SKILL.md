# 產品／服務理解與應用工作室

用簡單輸入，主動跨網站補產品、服務或混合方案的資料與文案依據，交一份研究筆記與五張有不同用途的理解圖。研究是本 Skill 的核心工作，圖片數量不限制研究內容。AI 圖是理解示意；原圖、服務資料、標籤及可核對來源才是證據。

## 1. 強制客戶對話關卡：先問，再做

每一個新 offer 工作，**必須先用自然語言問客戶，並等候回覆，才可研究、寫銷售文案、規劃視覺或生圖。** 這條規則優先於「直接完成」、「一次過」或 Quick Batch。不要把 URL、產品相或 AI 推測當成已獲客戶確認的銷售策略。

先讀本次工作區、原產品相／服務資料、URL 及已答內容，然後用一段簡短對話：先說明已知內容，再問 1–4 條真正會改變決定的問題。優先問：

1. 今次最先要賣畀邊類人／哪個市場？
2. 第一個要完成嘅銷售成果係甚麼平台或形式？
3. 最想主打的 offer、買家問題或 CTA 是甚麼？
4. 有冇必用／不可用的品牌素材、Logo、視覺 reference 或 claim？

已由客戶清楚回答的項目不可重問；若四項都已答，仍要用一句「我理解為……，可否按此方向進行？」取得確認。客戶可用短答，例如「台灣新手貓奴、IG、主打回放、用 A 圖」。未收到答覆或確認時，只可報告目前理解與缺口，**不得自行補預設市場、平台、受眾、主打、CTA 或進入下游製作。**

客戶答覆後才判斷 `product`、`service` 或 `hybrid`，並在筆記首行說明理由；已授權上網可主動研究，不重問同一資訊。用戶禁止上網便只用現有資料並列缺口。課堂互動見 [classroom-dialogue.md](references/classroom-dialogue.md)。

## 2. 先研究，再寫可用內容

讀 [public-product-research.md](references/public-product-research.md)，必須先讀用戶指定的參考網站及其相關詳情、標籤、FAQ，再主動搜尋其他網站。產品找同 SKU 官方、原產地、代理、零售商及公開客評／Q&A；服務找官方服務頁、方案頁、FAQ、公開案例、預約／交付說明與公開客評。產品同步找真實多角度照片、質地近拍與操作示範；服務同步找真實方法、交付物、過程或場景的可核對素材。研究要回答適用的買家問題：產品是配料／材料、結構、功能依據、用法、規格；服務是服務對象、問題範圍、方法、交付物、流程、時間／選項與買前條件。不能找到名稱就算完成。網站角色、實際讀取及新增發現必須可追溯；風格參考只支持設計，不支持宣稱。

把結果集中寫進 `offer-notes.md`（舊有 `product-notes.md` 可直接重用）：類型、身份與來源、特點→買家意義→可用文案、客戶問題、產品外觀鎖定或服務真相鎖定、未知／衝突、五圖計劃與交接。展示全部有用而不重複的發現，不以 3–5 句作內容上限；沒有足夠資料就如實說明。詳見 [product-baseline.md](references/product-baseline.md)。

## 3. 研究回顧關卡，再做五張理解圖

研究筆記完成後，先向客戶用簡短語言展示：已核對的 offer／受眾／主打、可用 claim、未知或不能講的內容，以及五張圖會各自解答甚麼。必須問「呢個理解同主打啱唔啱？可以做理解圖嗎？」並等待答覆。未確認時可按客戶修正研究筆記，但不得生成理解圖或交接詳情頁／廣告 Skill。

讀 [usage-cases.md](references/usage-cases.md)。預設五張合計，產品的 Appearance Sheet 已包含在內，不另加十個案例、三張使用圖或中間多角度批次。參考選題：

| 圖 | 要看懂甚麼 |
| --- | --- |
| 01 身份證據 | 產品：外觀與多角度 Sheet；服務：服務對象、核心承諾與真實接觸點 |
| 02 核心依據 | 產品：配料／材質；服務：已核對的方法、能力、團隊或服務內容 |
| 03 可見細節 | 產品：質地／結構；服務：交付物、體驗步驟或介面／工作細節 |
| 04 真實使用／流程 | 產品：合理使用時刻；服務：客戶如何開始、參與或接收服務 |
| 05 買前判斷 | 產品：規格／適配；服務：選項、適合誰、準備事項、FAQ 或下一步 |

預設完成五張獨立圖；產品圖 01 可包含多角度 panels，服務圖 01 可用清楚服務地圖／接觸點，不能假裝有實物角度。其餘四張各有用途，不再額外生成總覽。每張需增加一項買家理解。缺角度、質地、交付物或流程時先針對搜尋補來源，仍找不到才用受支持的替代題目並說明未覆蓋項；不得靜默減少張數。五張仍無法合理完成則記為部分完成，不能以空白格或重複圖湊數。用戶指定數量／只要文字時優先。

## 4. 快速完成及交接

圖像製作前讀 [visual-execution.md](references/visual-execution.md)，產品外觀 Sheet 另讀 [appearance-sheet.md](references/appearance-sheet.md)。產品每次帶真原圖與 [product-form-lock.md](references/product-form-lock.md)；未知背面、尺寸、成分及操作不由 AI 補成事實。服務每次帶已核對的服務範圍、流程、交付物與真實證據，不能編造客戶 Logo、評語、成效數據、case study、證書或 dashboard。混合方案同時帶兩個 Lock。

客戶確認後才可按已確認數量批次生成；不另要求逐張批准。只修硬錯；無法完成的圖如實記錄，不能交 prompt 冒充圖片。研究、圖像狀態與來源都留在同一份筆記，不逐張另建報告。

按 [handoff.md](references/handoff.md) 交接：先完成跨網站研究、可見文案素材和五張理解圖，**下一步必須實際載入本地 `brand-image-studio/SKILL.md`，並讀它的 `product-intake.md`、`product-detail.md` 與 `pdp-blueprint.md`，才開始詳情頁／服務介紹頁／廣告文案或生圖。** 保留市場、主打、來源、原圖或服務證據及品牌素材；第二個 Skill 負責 Direction、完整可排版文案與逐圖製作。尚缺必要圖片就保留部分完成狀態及原因，不自動跳過第一個 Skill；用戶明確要求文字交接或跳過時除外。
