# 品牌詳情頁與廣告工作室

接住已確認理解，完成本次需要的文案與圖片。產品／服務共用下列流程，只在證據、畫面及檢查項目分支。每個關卡先交可判斷內容，再問當關問題；以下確認規則適用所有 references。

## 1. 接手任務

讀 [product-intake.md](references/product-intake.md)，沿用研究、已答內容及有效確認，不重做問卷。單獨使用本 Skill 時，先簡述已知內容並補問受眾／用途、主打／CTA、交付需求等關鍵缺口，取得確認。已有相同確認直接進下一步。

產品核對畫面涉及的款式、外觀及操作；服務核對範圍、流程、交付及人物身份；混合在同一計劃分開兩者。資料不足只阻塞依賴它的部分，必要時交回理解 Skill 補該缺口，無需重跑全套。

## 2. 定風格與完整文案，再確認

先沿用已確認主打及買家問題；需要補客戶聲音分析才讀 [customer-insights.md](references/customer-insights.md)。

讀 [source-and-style.md](references/source-and-style.md) 核對品牌、原 Logo 及現有 Style。已有參考就真看並按 [reference-deconstruction.md](references/reference-deconstruction.md) 提取可用特徵；沒有時按 [creative-direction.md](references/creative-direction.md) 提出一個適合的候選，讓客戶確認。只在用戶要求比較時提供多個風格。缺 Logo 不阻止文案規劃，但品牌成品須放入真原檔。

| 本次成果 | 準備及按需讀取 |
| --- | --- |
| 單張廣告／海報 | 一個主張、一張計劃；讀 [image-plan.md](references/image-plan.md) |
| 詳情頁／服務介紹圖 | 依買家問題排頁；讀 [product-detail.md](references/product-detail.md)、[pdp-blueprint.md](references/pdp-blueprint.md) |
| 詳情＋廣告 | 共用研究與風格，廣告另做單訊息構圖；廣告延伸讀 [creative-packs.md](references/creative-packs.md) |
| Gallery／配套平台文案 | 只做已要求部分；讀 creative-packs |
| 加 Logo／改字／改尺寸 | 沿用現有計劃，只確認新增或有歧義的變更；讀 [native-images.md](references/native-images.md) |

張數跟用戶要求。未指定時按不同購買問題提出所需張數，放入本輪計劃確認；「做晒／今晚做」沿用當前範圍，不新增套裝、平台或廣告。

同一計劃保留一份視覺規則及每張製作卡，欄位見 [image-storyboard.md](references/image-storyboard.md)。向客戶展示風格方向、每張用途／畫面及全部實際對外文案；詳情頁有足以回答該頁問題的說明，廣告集中一個主張。內容不硬湊模組，亦不能只交標題代替完整文案。

問「方向同文案可以嗎？要改甚麼？」並等待確認才生圖。只要藍圖則交文字後停止。原有同版本確認持續有效；換主打、風格、關鍵文案或範圍，重確認受影響部分。

## 3. 按確認範圍製作

讀 [native-images.md](references/native-images.md)。每次生成一張獨立完整圖，只帶本張文案、素材、參考與必要限制。生成工具及付費範圍按當前有效授權。

- 預設批量（Quick Batch）：計劃確認後，以套內第一張作校準；AI 檢查通過再完成其餘，不額外生成無用途的測試圖。
- 先試一張（Review First）：用戶要求時，交代表圖等待答覆，再做已確認後續。
- 正式交付檢查（Final QA）：是額外驗收深度，並非另一套創作／確認流程；需要時讀 [output-contract.md](references/output-contract.md)。

原 Logo 用保留原檔的方式加入。產品外觀、服務內容、文案、Logo 或參考明顯錯誤要處理；工具缺失或失敗如實交代。續做與局部修正見 [continuation-and-review.md](references/continuation-and-review.md)。

## 4. 成品 review

展示實際圖片、已完成張數及重要問題，問客戶選用／修改／確認。只重做受影響頁；改方向先回第二步。候選稿、正式檔案驗收及客戶確認分開記錄，不能代客戶確認。

本 Skill 不操作投放、CRM 或發布。課堂對話例子見 [classroom-dialogue.md](references/classroom-dialogue.md)。
