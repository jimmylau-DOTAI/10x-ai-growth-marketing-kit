# Complete text storyboard output

## Three independent stories

Story pattern is the order of ideas; spoken style is how the voice sounds; visual treatment is how the scene looks. Keep those choices distinct. Reuse selected preferences without reopening them.

For three directions, use meaningful alternatives suited to the source: for example, reassurance with guided checks, a supported misconception correction, and practical steps. These are examples, not three fixed templates. Each file needs its own complete story; no shared remainder or link to another file for missing narration. The opening, explanation route and viewer experience must visibly differ, while facts and CTA stay consistent.

## Inside each Markdown file

1. **Direction note:** title, audience, working spoken style and viewer feeling; source reference and claim limits; target duration and estimated/verified timing. Keep these outside the narration.
2. **完整口播:** continuous, copyable recording text with natural paragraph breaks. No timestamps or camera instructions. It must equal the ordered scene voiceovers after whitespace normalization.
3. **逐幕文字分鏡:** one compact table using the columns below.
4. **素材提示:** group existing assets, proposed recording and possible general illustration. Identify scene ids and source/rights/CTA gaps once. This is a plan, not a claim that assets exist.

Use this scene table:

`幕／估算時間 | 完整口播 | 螢幕短句 | 畫面重點與動作 | 觀眾感受／理解轉變`

Full voiceover is literal narration, not a summary. Screen copy is usually one short conclusion; choose a length readable in that scene and language. Mandatory qualifications must remain legible or audible rather than being removed for brevity.

Describe what fills the frame, where viewers should look and one change tied to a spoken cue. For example: 「講『一次一樣』時，其餘選項收起，只留當次檢查項目。」Do not prescribe code, HTML modes or millisecond timings in a text-only task. Don't force a shot change when the idea needs a quiet hold.

If filming is relevant, explain A-roll as the main speaking shot and B-roll as supporting footage once; include position, focal point and action when useful. A faceless narration or illustrative route is equally valid. Proposed diagrams must not pretend to be real demonstrations. Technical shot plans and machine-readable exports are optional, only when requested by the user or an actual downstream consumer.

## Review before delivery

- Open every saved candidate; check the full story is independently readable.
- Compare continuous narration with ordered scene voiceovers, ignoring whitespace only. Fix omissions or paraphrases before calling the candidate complete.
- Compare A/B/C for different reasoning or narrative progression, not just three headings.
- Check scene timings against spoken length and pauses. Report an estimate, not verified duration, unless a real read/audio exists.
- Check a reader can imagine the scene without specialist layout vocabulary, and that the motion serves the message.
- Verify source boundaries, actual style provenance, asset status and one CTA. Keep review status separate from user approval.
