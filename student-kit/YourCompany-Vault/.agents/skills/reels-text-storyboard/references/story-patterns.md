# Choose a story for the viewer

| Pattern | Choose when | Useful sequence | Evidence limit |
| --- | --- | --- | --- |
| pain-to-solution | A real problem and a supported explanation exist | recognisable situation → why the obvious fix falls short → better decision → application → next step | Do not invent fear, before/after results or a single root cause. |
| proof-first-demo | A real output or demonstration is available | result → how it happened → important step → limit → next step | If proof is absent, offer an explanation route rather than a fake demo. |
| step-by-step-teaching | The viewer can perform a small task | outcome → required input → 2–5 observable steps → check → next step | More steps may need a narrower task; explain what each action changes. |
| system-explainer | The viewer needs to understand relationships | question → representative example → parts and relationships → practical decision → limit | A diagram explains a mechanism; it does not prove a product feature. |

For a product sheet, show supported uses and selection criteria. For an interview, distinguish speaker experience from general evidence. For a service explainer, describe actual scope and avoid promising outcomes. One route may suit many industries; none requires a brand-specific palette or vocabulary.
