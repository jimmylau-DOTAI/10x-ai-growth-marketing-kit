# Image Style Lab

拆解一張圖想令觀眾注意、感受或理解乜，以及第一眼嘅字圖安排點樣做到；將有用嘅方法轉成自己品牌可重用嘅 Style。沿用已知資料與喜好，依今次要求做拆解、試圖或保存，唔每次重新訪談。

如 Reference 實際展示嘅係文字語氣或可重複工作方法，仍可分別建立 Tone 或 Skill candidate；只讀相關既有 reference，唔為一張圖強行產生所有文件。任何候選都要用戶明確要求才保存。

## 從動機睇第一眼

先看實圖，分清來源靈感、已確認品牌示例、改圖目標及失敗例子。用一句話連起「這張圖想帶出甚麼 → 第一眼見到甚麼 → 哪個視覺關係支持它」。未有用戶／作者說明嘅動機係推測；用戶講過嘅喜好先記為確認，不宣稱已測得觀看順序或成效。

只拆影響判斷嘅特徵，唔逐格填清單：

- **第一眼排版**：標題、臉、產品或其他主體點樣爭取注意；大小反差、位置、靠近、重疊、留白和方向如何帶出主次。位置本身唔係答案，要講其作用。
- **字形與色彩**：字重、描邊、陰影、字距、文字容器，以及明暗、冷暖、飽和度如何令重點突出。唔只抄色碼或猜 exact font。
- **角色與質感**：表情、動作、視線、照片／插畫、光影、毛髮／物件材質如何支持內容；冇人或動物嘅圖亦可以靠字、物件、空間成為焦點。
- **裝飾與節奏**：細線、圖示、形狀如何導讀、強調或帶出情緒；可省略、可變奏，唔因來源有便要求每張都有。

收斂為少量「喜歡嘅效果／有用嘅視覺關係」及可變部分，連返實圖理由。唔把每個觀察升格為必守規則。用「主標先搶眼、主圖托住情緒、次要資訊退後」等關係描述，唔用百分比、座標、固定格數或左右分欄定義 Style；用戶明確要求複製版面時才按其精度處理。

## 放到自己的內容與平台

沿用已知用途，分清 IG 單圖、Carousel 封面／內頁、Blog Banner 等閱讀任務。平台界線用來處理比例、閱讀密度及裁切，唔用來強制每頁排法；實際像素交由出圖 job 確認。

新內容想觀眾先記住乜，就先決定視覺重心。比較、流程、解釋等可幫助理解關係，但唔需要分類表或指定構圖配方；有流程亦唔代表必須畫箭嘴。同一系列靠字形氣質、色彩角色、影像質感及注意力層級連接，格數、位置、背景、照片數量按內容決定。合理時可以沿用版面，唔為求不同而重排。

從 current brief／指定 Vault 讀品牌 DESIGN／TONE、真 Logo 與素材。用自己品牌嘅色彩角色、字形及影像氣質承接來源嘅吸引方法；保留自然膚色、毛髮及真產品。缺必要品牌資料才問，唔把來源身份、原文、包裝或 claims 直接帶入。

要試圖時讀相容嘅 `ai-social-image-maker`，交當次內容、用途／尺寸、真素材、必要實圖及簡短視覺意圖。參考圖標明供看字形、色彩、質感或構圖；未要求照排就唔把示例當模板。窄修改保持用戶指定嘅其他部分；只拆解或保存時不額外出圖。

## 保存成可重用 Style

沿用用戶 Vault 現有格式目錄及索引；同款更新沿用 ID、增加 revision、保留可回復版本。保存前講清檔案及影響範圍，保存後讀回內容、示例及引用。

只需 `STYLE.md`＋`assets/reference-images/` 必要圖片。STYLE 簡短包含：

- **來源及動機**：實圖、第一眼吸引方法，分清觀察、推測與用戶喜好。
- **用途與自由度**：適用平台／位置、希望保留嘅感覺與視覺關係、可隨內容改變嘅部分；未試格式如實標示。
- **我的品牌版本**：品牌來源、轉化方法、自己的示例、revision及用戶確認範圍。

日常出圖先看已確認品牌示例。示例用來理解感覺與方法，唔要求每張放齊同一套元素；來源只在需要回看原因時讀。只在用戶確認適配圖後記為已選品牌 Style；喜歡拆解方法不自動等於批准所有試圖。失敗圖保留為歷史，唔混入已確認示例。

設計方法寫在 STYLE 內，唔另生重複 DESIGN／拆解報告；品牌共通 DESIGN／TONE仍可引用。當次文案、像素、Logo放置、工具及QA留job，唔變成永久排版規則。保留style_id、revision、用途、來源限制及確認狀態；保存不自動改平台預設或發布。

## 文字與工作方法

只有 Reference 確實展示可重用嘅用字、節奏、Hook 或 CTA 行為，才讀 [tone-extraction.md](references/tone-extraction.md) 建立 `TONE.md`；原句、個人經歷與未核實 claim 留在來源，不變成語氣規則。

只有 Reference 確實展示可重複嘅輸入、判斷、輸出與錯誤處理，才讀 [skill-extraction.md](references/skill-extraction.md) 建立 `SKILL.md` 和 evals。一次示範只支持候選；同一輸出要先以不同正常情境與 holdout 測試，才可提議採用。

## 驗收

對照原圖同新圖，判斷第一眼能否傳達今次重點、保留喜歡嘅吸引方法、適合自己品牌及平台。不能只以位置相似或換圖換字當成功；亦唔要求為證明創意而刻意不同。文字、尺寸、真素材及實圖QA由maker處理。

交代實際更新、示例位置及未驗證部分。文件更新、實際出圖、用戶確認係不同證據，唔以一次本地成功承諾日後每次輸出。
