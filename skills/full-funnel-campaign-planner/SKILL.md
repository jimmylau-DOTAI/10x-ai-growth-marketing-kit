# Full Funnel Campaign Planner

## Overview

將散亂 Marketing Idea 變成可執行 Full Funnel。先讀現有資料，再用 Grill Me 補齊真正影響策略嘅決定；不要用假設填滿一份表面完整嘅 Plan。

## Boundaries

使用本 Skill 規劃多階段 Campaign。單一 SEO 文章、單一社交 Post 或單一內容分析應交由專門 Skill。

本 Skill 只建立計劃、Brief 及 Handoff。不得自動發佈、發訊息、改廣告預算、處理客戶資料或宣稱已獲批准。

## Workflow

### 1. Read current state

讀取用戶提供嘅公司、Offer、客戶、渠道、過往 Campaign、數據、團隊、預算及期限。以四種狀態整理：

- `CONFIRMED`：來源已確認；
- `ASSUMED`：為繼續討論而暫定；
- `OPEN`：需要決定；
- `BLOCKED`：缺少資料令規劃無法成立。

可從資料找到嘅答案不要重複問。

### 2. Grill missing decisions

如關鍵決定未清楚，讀 [grilling-intake.md](references/grilling-intake.md)。一次只問一題，並提供：

1. 點解呢題重要；
2. 2–3 個可行選項；
3. 一個建議答案及原因；
4. 它會影響 Funnel 邊一部分。

等待回答後才問下一題。不要一口氣派發問卷；亦不要未確認受眾、Offer 或 Outcome 就虛構 Budget、KPI、渠道或內容量。

### 3. Build the funnel

讀 [full-funnel-framework.md](references/full-funnel-framework.md)。只加入服務今次 Business Outcome 嘅 Stage：

`Discover → Engage/Capture → Nurture → Convert → Retain → Refer`

每個 Stage 寫清楚 Audience State、Goal、Message、Proof、Channel、Asset、CTA、Success Signal、Owner 及 Status。不需要嘅 Stage 標示 `NOT REQUIRED`。

### 4. Prioritise 90 days

按能力與依賴關係分類：

- `NOW`：立即解除卡位；
- `NEXT`：未來 30 日建立；
- `LATER`：31–90 日測試或擴大；
- `SKIP`：今次刻意不做。

每項包括 Owner、Reason、Dependency 及 Success Signal。

### 5. Route execution

按 [routing-and-delivery-gates.md](references/routing-and-delivery-gates.md) 建立 Specialist Handoff：

- 市場或社交內容研究 → `social-content-research`
- SEO／AI Search 內容 → `seo-geo-content`
- 社交文案 → `social-post-writing`

Planner 不代替 Specialist 完成內容。

## Output contract

使用 [full-funnel-plan.md](assets/full-funnel-plan.md) 輸出：

1. Campaign Summary；
2. Current State；
3. Full Funnel Map；
4. 90-Day Priorities；
5. Content and Skill Handoffs；
6. Measurement、Risks and Approval。

每個執行工作使用 [campaign-handoff.md](assets/campaign-handoff.md)。

## Quality gate

- 一個 Campaign 只有一個主要 Outcome、Audience、Core Message 及 Main CTA；
- Claim 有 Proof 或清楚標示缺口；
- KPI 有基準、來源或標示為待驗證假設；
- 計劃符合 Team、Budget 及 Timeline；
- Handoff 可由另一個 Skill 獨立執行；
- Draft、Approved、Published 狀態沒有混淆。
