# Social Content Research

## Overview

將一條社交內容變成可驗證嘅研究，而唔係憑印象抄橋。核心流程係：`Read → Understand → Analyse → Adapt`。

## Required input

最少需要一項：

- URL；
- 圖片或截圖；
- 影片或音訊；
- Caption、逐字稿或貼文文字。

品牌、受眾、產品及目標平台屬於選填。未提供時，完成內容研究，但不要虛構品牌角度。

## Workflow

### 1. Read

先確認實際取得嘅證據。將狀態標為：

- `FULL`：正文及主要媒體已讀；
- `PARTIAL`：只讀到部分正文、預覽或部分媒體；
- `IMAGE_ONLY`：只有圖片或截圖；
- `BLOCKED`：內容無法存取。

URL 優先用可用瀏覽器閱讀。影片先讀官方字幕；沒有字幕時才轉錄音訊。圖片或 Carousel 需要逐張讀取。不可將標題、縮圖或搜尋摘要當成完整內容。

### 2. Understand

記錄主題、核心觀點、重要例子或數字、原本 CTA。將原內容證據與 AI 解讀分開。

### 3. Analyse

按需要閱讀 [analysis-checklist.md](references/analysis-checklist.md)，檢查 Hook、受眾張力、結構、Proof、格式、CTA、弱點及過度承諾。只分析實際看得到嘅元素。

### 4. Adapt

分開輸出：

1. 值得學嘅內容機制；
2. 不應直接照搬嘅文字、Claim 或品牌元素；
3. 重新發展嘅原創 Content Angles。

每個新角度都要改變至少一項：受眾、問題、證據、觀點、例子或內容格式。

## Output contract

按用戶要求調整深度；完整版本使用 [research-output-template.md](assets/research-output-template.md)：

1. Access state；
2. 我實際讀到乜；
3. 一句總結；
4. Hook 與結構分析；
5. 值得參考嘅機制；
6. 風險或盲點；
7. 三個原創 Content Angles。

如果用戶只要 Summary，只輸出 access state、實際讀到嘅範圍及總結。

## Quality gate

- Access state 與實際證據相符；
- 沒有補寫看不到嘅 Caption、畫面或數據；
- OCR、字幕、人物姓名及數字已做合理核對；
- Evidence 與 Interpretation 分開；
- 新角度不是原文改幾個字；
- 沒有聲稱內容「有效」而缺乏成效證據；可改寫為「可能有效嘅機制」。
