# Content jobs

先按手上證據揀一個 job。唔好因為某種格式近期受歡迎，就將材料硬塞入嗰種寫法。

## `hot-take`

- 適合：有一個清晰立場，而且能夠交代理由、限制或反例。
- 最低證據：可解釋嘅觀察、經驗或 source；要分清事實同個人判斷。
- 內文形狀：立場 → 點解一般講法有問題 → 一個具體理由／例子 → 判斷。
- 無效用法：為反而反、無 source 嘅絕對結論、將少數經驗扮成普遍定律。
- 自然收尾：講清你會點揀、咩情況例外，或者問讀者一個真實可答嘅問題。

## `reaction`

- 適合：回應一段新聞、公開 Post、產品更新、事件或一句可核對說話。
- 最低證據：目前仍可存取嘅 source、正確脈絡、事件日期；未核實就標示。
- 內文形狀：發生咗咩 → 最值得留意嘅位 → 你嘅解讀 → 對讀者有咩影響。
- 無效用法：只睇標題就評論、假裝即時資料仍然有效、搬運原文無新增判斷。
- 自然收尾：指出下一個值得觀察嘅訊號，唔好硬加大道理。

## `personal-story`

- 適合：有已核實嘅第一身場景、轉折同事後理解。
- 最低證據：真實人物身份、時間線、自己確實經歷過嘅細節；唔確定就刪。
- 內文形狀：具體一幕 → 當時選擇／錯判 → 發生咩轉變 → 今日點理解。
- 無效用法：代 source 發明內心戲、合成「真實故事」、為煽情加對白。
- 自然收尾：留低一個仍然帶住嘅判斷、習慣或未解問題。

## `build-note`

- 適合：分享正在做、啱啱完成或失敗咗嘅實際工作。
- 最低證據：真實 artifact、版本、測試、截圖、操作記錄或明確 progress。
- 內文形狀：想解決咩 → 今次試咗咩 → 邊度得／唔得 → 下一步。
- 無效用法：用概念冒充 progress、將 prototype 寫成已推出、隱藏重要限制。
- 自然收尾：下一個驗證動作，或者邀請同類實作者交換做法。

## `review`

- 適合：評價自己真正用過嘅產品／服務，或者清楚披露只做公開資料研究。
- 最低證據：實際使用場景及限制；若非親身使用，明示 research-only。
- 內文形狀：用嚟做咩 → 最有用／最阻手嘅位 → 適合邊類人 → 結論同限制。
- 無效用法：未用過扮用過、affiliate／利益關係不披露、用規格表代替體驗。
- 自然收尾：具體建議「邊個值得試／邊個可以跳過」。

## `anti-pattern`

- 適合：拆解一個常見失敗、風險或表面合理但會出事嘅做法。
- 最低證據：可說明嘅失敗案例、風險機制或可信 source。
- 內文形狀：常見做法 → 點解令人誤判 → 實際代價 → 較穩陣替代方案。
- 無效用法：只用恐嚇字眼、影射個人、無機制就斷言「一定失敗」。
- 自然收尾：一個可以即刻檢查或停止嘅動作。

## `curated-list`

- 適合：讀者真係要喺多個選項之間揀，而你有清晰篩選準則。
- 最低證據：多個真實選項、可核對資料、選入／排除準則。
- 內文形狀：先講選擇情境 → 準則 → 每項用途／限制 → 點揀。
- 無效用法：為湊數堆名、排名無準則、所有選項都寫成「必試」。
- 自然收尾：按預算、能力或場景畀一條最短決策路徑。

## `how-to`

- 適合：有可重做嘅步驟，而且知道成功同失敗點樣判斷。
- 最低證據：自己跑過或有可信 source 支持嘅流程、必要前提、檢查點。
- 內文形狀：目標／前提 → 有次序嘅步驟 → 成功訊號 → 常見失敗同修正。
- 無效用法：未驗證步驟、跳過必要條件、只講按鈕但無 outcome check。
- 自然收尾：叫讀者先做最細可驗證一步，或者提供完整筆記嘅真實 link。

## Commercial overlay

商業意圖係 overlay，唔係第九個 content job。先揀上面一個 job，再決定需唔需要 offer、CTA 或 disclosure。

- 清楚講明利益關係、價錢／期限嘅 source date 同適用條件。
- CTA 要承接正文價值；唔好由個人故事突然跳去硬銷。
- 無已核實 landing page 就用 `[LINK TBC]`，唔好生成假 link。
- 「有興趣留言」唔代表已經有自動回覆、交付或客服流程。
