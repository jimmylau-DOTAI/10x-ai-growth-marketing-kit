# Source-faithful examples

以下係虛構教學情境的結構示例；每例附聲音與事實輸入，不是已發布內容或成效證據，也不是所有品牌的固定模板。按真正 brief 選擇，勿複製人設／結果。JSON 內的換行是交付文字的一部分，可交 count_segments.py 計數。

## `complete-single-500` — one judgment

Voice input：中性組織，香港專業口語，無 Emoji。Source：會議紀錄應保留決定、負責人及下一步；沒有量化結果或自動交付功能。Objective：一個完整觀點，不要 Link。

```json
{
  "segments": [
    {
      "id": "root",
      "text": "會議紀錄要留得住下一步。\n\n決定咗乜、邊個跟進、仲差咩資料，寫清楚先方便接手。\n\n如果只將討論縮短，之後仍然要由頭追問。\n\n整理完，先檢查有冇負責人同下一個動作。"
    }
  ]
}
```

## `notes-link-reply` — same source, different voices

共用 source：工作坊先做 10 分鐘整理練習，再討論；參加者帶舊筆記，不需先識軟件。完整介紹已寫好，公開 URL 未確認。以下兩組分別是一篇稿，不能混在同一條 thread。

### A｜親切同行者

Voice input：自然廣東話，短問題切入、語意相連可換行，可用適量分隔但無指定符號。CTA：閱讀完整介紹。

```json
{
  "segments": [
    {
      "id": "root",
      "text": "筆記愈儲愈多，下次要用仲搵唔搵得返？\n\n呢場工作坊會先做 10 分鐘整理練習，再一齊討論。\n帶一份舊筆記就得，唔使先學識另一套軟件。\n\n先由手上嗰份開始，睇清楚自己想搵返啲乜。"
    },
    {
      "id": "reply-1",
      "text": "工作坊完整介紹：\n[LINK TBC]\n\n入面有練習安排同準備事項。"
    }
  ]
}
```

### B｜簡潔專業組織

Voice input：香港書面繁中、冷靜直接，只有普通標點與留白，不用 Emoji。共用事實與 CTA 不變。

```json
{
  "segments": [
    {
      "id": "root",
      "text": "整理筆記，可以從一份現有材料開始。\n\n工作坊先安排 10 分鐘整理練習，再進行討論。參加者只需攜帶舊筆記，毋須預先學習軟件。\n\n先確認需要重用的內容，再檢視整理方式。"
    },
    {
      "id": "reply-1",
      "text": "工作坊完整介紹：\n[LINK TBC]\n\n包含練習安排及準備事項。"
    }
  ]
}
```

## `staircase-thread` — progression chosen for this material

Voice input：社區資料整理小組，清楚、克制，段落提示可用普通標題。Source：先列待搬檔案清單，再建立副本抽查；抽查未完成前保留原目錄，不刪原檔。這個例子需要分層，不代表所有 thread 都應有三段。

```json
{
  "segments": [
    {
      "id": "root",
      "text": "搬資料前，先知道自己要搬乜。\n\n列清檔案範圍，先有清單可以對照。下面接住講副本同抽查。"
    },
    {
      "id": "reply-1",
      "text": "副本先行\n\n先建立副本，再抽查能否打開、內容是否齊全。\n\n只見到複製完成，仲未完成內容檢查。"
    },
    {
      "id": "reply-2",
      "text": "原檔暫時保留\n\n抽查未完成前，保留原目錄。呢輪唔刪原檔。\n\n先用清單對照一次副本，再決定下一步。"
    }
  ]
}
```

## Bad／good mobile paragraph

同一個中性聲音，只示範語意停頓；不是固定行長。

Bad：

```text
換過工作流程之後如果只更新FAQ答案但冇交代負責人同下次覆核日期其他同事之後再睇返就可能唔知邊段仍然適用所以整理時要連埋呢兩項一齊保留。
```

Good：

```text
工作流程換咗，FAQ 亦要有人跟進。

更新答案時，連負責人同下次覆核日期一齊保留。

其他同事再睇返，先知道可以搵邊個確認。
```

## Same source: summary, word swap, conversational post

只在遇到「已改廣東話但仍似摘要」的 feedback 時讀此例。虛構 source：FAQ 模板有問題、負責人、下次覆核日期三欄；流程改動後需人手更新，內容正確性由團隊判斷。Blog 有整理步驟，URL TBC。Voice：香港口語同行者；今次要求適量分隔。下列比較固定事實與 Blog 目的，不代表所有品牌都用這種聲音。

摘要式：FAQ 模板設有三欄。流程改動時，負責人須更新答案及覆核日期。完整步驟見 Blog。

只換字：講真，FAQ 有三欄㗎。先填問題，再填負責人，跟住填日期。想知就睇 Blog 啦。

第二種改法仍然沒有講清為甚麼值得讀。以下完整稿從一個可回答的問題出發，解釋跟進責任、交代限制，再承接 Blog；分隔把意思分層，不用口頭禪撐語氣。

```json
{
  "segments": [
    {
      "id": "root",
      "text": "FAQ 寫好咗，之後邊個會返去改？\n\n流程一轉，舊答案就未必啱用。\n答案旁邊，有冇留低邊個跟？\n\n▍所以，答案以外都要留線索\n\n呢份模板會連問題、負責人、下次覆核日期一齊記低。\n流程改咗，由負責人人手更新，再填下次覆核日期。\n\n有咗模板，仍然要有人睇返答案啱唔啱。\n完整整理步驟放喺回覆。"
    },
    {
      "id": "reply-1",
      "text": "想睇點樣整理，可以跟住 Blog 嘅步驟：\n[LINK TBC]"
    }
  ]
}
```

重寫改變了看事情的起點、解釋和句子銜接；作者、限制及 CTA 沒有改變。符號與措辭不可直接套用到另一品牌。只有模板真有提醒功能的 source，才可推翻本例的手動限制。

## Same boundary, three Hook Levels

Source：某份內部目錄缺少版本與負責人；只係今次檢查，不能推論所有團隊。三個替代 Hook 不是一條 thread。

```json
{
  "segments": [
    {
      "id": "L1",
      "text": "今次檢查目錄，發現版本同負責人都未列清。"
    },
    {
      "id": "L2",
      "text": "今次搵到檔案之後，仲差一步：確認邊個版本可以用、邊個負責。"
    },
    {
      "id": "L3",
      "text": "搵到檔案，仲未等於可以放心用。至少今次呢份目錄，版本同負責人仍然未清楚。"
    }
  ]
}
```
