# Source depth guide

用 source 決定今篇值得講甚麼、要講幾深入。交付格式與 CTA 見 [mobile-rhythm.md](mobile-rhythm.md)，內容單位數量不決定帖數。

## 選題先於篇幅

1. 先讀已有 Source Guide 或 supplied source，找出目標讀者會關心的一個問題。
2. 選支持這個問題的場景／觀察、解釋、條件、例子或下一步，保留各自的來源依據。
3. 多個互不相關主題留作其他選題。用戶要全面涵蓋時才做總覽；原文有十個 heading 不代表今篇要搬晒十個。

同一結論換句話、加 Emoji 或拆行不算新內容。安全條件與必要行動跟相關建議一齊出現，唔留作懸念。

## 長度怎樣判斷

- 當次指定篇幅優先，其次讀適用 TONE。要求「約 300 字」就向 300 靠近，250–350 作彈性參考，唔將 250 當寫到即停的目標。
- 未指定時，完整 Blog 轉寫主帖可以約 300 字起稿，按 source 和品牌節奏調整。取消「至少三個單位」門檻：一個題目亦可有足夠解釋與例子寫得完整。
- 先補足讀者需要的原因、具體細節、條件或理解，再修順句子。來源確實不足就交代缺口，不新增親身經歷、假對話或未支持建議。
- 純提問、短觀點或明確要求簡短時，按任務完成即可；唔套 Blog 主帖篇幅。500 是本 Skill 的每段計數上限，唔係風格分數。

## 深度 read-back

- 開場答應解釋的事情有沒有講清楚？真心請教有沒有讓讀者知道怎樣接話？
- 每一段有沒有新意思，還是同一句反覆包裝？觀察和例子可以放同一主帖的不同段落。
- `notes-link-reply` 的 root 已完整；reply 只負責相關延伸和 CTA。`staircase-thread` 的內容回覆才需要逐層增加理解。
- 約 300 字有沒有真正展開內容？偏離目標時在 receipt 簡述原因，不能只報「少於 500，PASS」。

receipt 的 `source_depth` 用一句記錄選題、所用內容與篇幅理由。Source map 留在工作紀錄，唔當成讀者文案。
