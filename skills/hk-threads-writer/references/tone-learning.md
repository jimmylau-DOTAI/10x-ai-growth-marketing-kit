# First post, TONE and reuse

用第一篇可討論的真實稿建立語氣，再將用戶確認的寫法保存到**當前 Project**。適用於首次建立、空白 TONE、具體改稿 feedback 及要求「以後沿用」；已有足夠規則時直接讀取起稿。

## Locate and draft

- 先由當前 Project 定位 `Threads/TONE.md`，再讀正文和適用樣本。已有檔案就更新原檔，唔另建競爭的 STYLE.md；未有檔案才在**當前 Project**建立 `Threads/TONE.md`。平台共用 TONE 是學生啟動頁，不可寫入品牌身份、行業、受眾或單一 Project 樣本。
- 不可因當前 Project 未有 TONE，便讀取另一個 Project 的 TONE／sample；只可用當次 brand／brief 和該 Project 可讀資料寫 `neutral_fallback` 或 `partial_pending_review` draft。
- TBC／empty_verified_layer 代表部分內容待建立。先用共通品牌、當次身份、已認可樣本及 feedback 補足今次起稿所需；保留未有依據的項目，不要求學生填寫風格表。
- 由 AI 說明一句「以甚麼身份，同甚麼處境的讀者，以甚麼關係談甚麼」，再交完整試稿。只有關鍵身份衝突或缺口才問最小問題。用戶已指定題目／批准方向／要求全文時直接完成，唔重啟角度選擇。
- 有當次認可 sample 或明確風格 reference 時，起稿前做內部 `style-fit`：今篇的讀者目的、會借的具體觀看角度／推進方式、以及不會帶過來的身份、claim 或機械格式。sample 未實際改變正文，不可只在 receipt 掛名；候選 sample 仍不可自動升格成長期 TONE。
- 身份影響作者留意哪些細節、如何理解讀者的取捨，以及為何值得開口。同行交流可從共同處境分享觀察；專業公告可直接交代資訊。不要把「共同生活開場」或「朋友口吻」硬套所有品牌。
- 交流稿另定清楚本篇對話身份：作者可以 `answer`、`share-and-invite`，也可以 `ask-to-learn`。後者要留下讀者可分享真實經驗的問題；按需要補充情境或有用追問，不設句數配額、不搶答或重複催答。這個選擇按篇記錄，不能由一篇提問稿推成每篇必須問。
- content job 用來描述適合的內容，不是覆蓋說話關係的模板。討論稿不必收齊 Blog 的所有章節；涉及實際風險的建議仍保留相關條件及必要行動。

## Approval and scope

- 分清「呢篇可以」的稿件接受，與「以後沿用／幫我記低」的保存授權。具體保存要求已存在時沿用，不重問；只有模糊稱讚時可交簡短保存建議，唔自行改 canonical TONE。
- 核對批准指向的 exact copy 和範圍。只批准三句開場，就以三句作 anchor；未批准的新增正文、被退回稿或測試稿不能一併標 approved。
- 保存前說明實際檔案、擬更新內容與適用範圍。尊重所在 Vault 的路由及寫入權限；首次明確指定語氣是用戶設定，不冒充累積 performance learning，不為湊訊號數發明 receipts。

## Save in the existing structure

- 檔案只收本次確認的可重用規則：作者與讀者關係、看事情角度、開場、香港語域、句長與分段、符號／回覆／Link 的用途。提問樣本要寫清 `conversation_stance`、主問題、答案留給誰、甚麼情況仍要直接說明。標明適用情境；一篇純文字例子不代表禁用符號，一篇問句不代表每篇必須提問。
- 加入簡短對照與原因：原句／改後句／用戶 feedback。AI 抽出的推論須標待確認；不能把編輯解讀寫成用戶原話。
- 完整樣本保留實際文字、換行及 reply 次序，沿既有 artifact／Project 位置保存；TONE 連回樣本。若平台案例目錄規定只存索引，就只加一行連結，不另複製完整稿。Standalone 沒有既有結構時可把短樣本放 TONE 內。
- 保存 sample approval、規則確認範圍及來源；沿用原有 metadata 慣例。部分欄位仍 TBC 時不可把整份標 fully approved，不發明 owner。
- Source facts、優惠、活動 CTA、URL、醫療建議和發布批准留在當次 source／brief，唔寫成永久語氣。用相對連結，唔把某公司的身份或檔案位置寫入共用 Skill 或平台共用 TONE。
- 更新前 duplicate-check；保留無關段落及仍適用規則，相同樣本／同一批准重跑不新增重複記錄。更新後重讀 TONE、sample 和索引，檢查文字、狀態及連結，再回報實際路徑和範圍。

## Reuse and verify

下次讀 TONE 及一篇適用樣本，按新 source 寫新稿。當次明確要求優先；例如今次要正式公告、無符號，就不硬套舊有傾偈結尾。題目不同可改變篇幅、符號或 mode，仍保持適用的作者關係。

核對三個實際證據：

1. 指出樣本哪一句呈現選定的身份／角度，以及新稿哪一句承接同一關係；只寫「親切」「我哋」不算對照。
2. 檢查新稿有沒有復發已退回的問題，例如由分享突然轉成訓話、預設讀者心急、文尾硬加問題。內容自然需要直接指引時，按任務判斷，不以「任何品牌都能說」作一刀切失敗規則。
3. 對 exact final copy 跑 count，並確認新稿仍為 draft／待人類語氣確認。讀回、字數和連結 PASS 只證明機械或檔案結果；新題材的聲音要由用戶驗收。
