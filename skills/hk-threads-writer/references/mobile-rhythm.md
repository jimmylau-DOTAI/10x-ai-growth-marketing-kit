# Mobile rhythm and delivery modes

一個段落是一個閱讀停頓；一則 Post 可以有幾個段落。段落與回覆帖分開判斷。

## Mode selection

按「當次要求 → 已確認 TONE／Project 偏好 → 以下預設」決定：

- Blog 轉寫並引導閱讀：完整主帖＋第一個 CTA reply，使用 `notes-link-reply`。
- 沒有延伸 link：一則主帖完成本題，用 `complete-single-500`；有幾個相關重點亦可在主帖內分段。
- 用戶明確要求樓梯、或確實需要分帖展開而現有偏好容許，才用 `staircase-thread`。每層有獨立工作，不按 source heading／重點數自動拆帖。
- 已指定不出樓梯時，按 [source-depth-guide.md](source-depth-guide.md) 收窄題目並完整交代，必要條件不能因格式而刪除。

## Delivery modes

### `complete-single-500`

交一個 `root`，在主帖內完成觀點、解答或討論邀請。可有多個空白行分隔的段落，無需 reply 補回題目承諾。

### `notes-link-reply`

交 `root` 及 `reply-1`。主帖完整，reply 按下方 CTA 規則寫。Link 未提供／未核實用 `[LINK TBC]`，在正文以外說明待補；保持可用的 CTA 草稿，唔聲稱連結已可用。

### `staircase-thread`

交 `root`、`reply-1`、`reply-2`……每段推進一層理由、條件、例子或下一步；root 點出題目與核心，必要安全資訊放相關建議前。主要 CTA 放最後相關回覆，不重複催促。

三種 mode 每個 segment 都獨立經 Python `len(text) <= 500` 檢查。篇幅目標見 source-depth-guide.md。

## 每個重點一段，段與段之間留白

- 一段只發展一個重點；轉場、轉理解、補另一個例子或提出問題時，用空白行分開。
- 同一重點的解釋可以留在同段，通常一至三句。單換行只是段內停頓，不能代替兩個重點之間的空白行。
- 長句交代必要脈絡，短句落重點。避免密牆、未完句被切斷，或每句同樣長。合理的一句段落可以保留，不一律判成碎句。
- 分段不要求短標題、編號或符號。Emoji 可表情或承接語氣，按已確認風格選用；唔設必用位置、數量或符號配對。
- `▍`、`→`、`👇` 等只在文意需要時使用；不能暗示不存在的步驟、因果或下一層。已取消的強制符號要求不從舊樣本恢復。
- 交付 copy 同計數 payload 必須保留相同空白行；Markdown 預覽好睇不等於可複製內容有分段。

## Blog reply CTA

reply 沿用主帖的作者與香港語氣。從今篇延伸到 Blog 內一個具體可讀內容，再自然邀請讀者撳入去；URL 獨立一行。可以一句完成，唔固定套三句模板。

- 品牌 Blog：可按已確認 brief 以品牌身份帶入，避免只寫「資料來源」或裸 link。不能虛構清單、工具、下載或文章沒有的答案。
- 外部推薦文章：一樣可以有閱讀理由和邀請，清楚交代係別人的文章，不冒稱「我哋整理」。內部 source receipt 與讀者看到的 CTA 分開。
- 測試要求「當作品牌 Blog」時，可照該假設寫品牌 CTA；把假設記在 receipt。外部 source URL 不因此變成已核實品牌發布 URL，品牌目的地未知就用 `[LINK TBC]`。
- Blog 閱讀是主要動作時，主帖可自然留一個相關經驗問題；唔再疊加收藏、分享、追蹤、留言領取等多重要求。不要因「一個主要 CTA」刪掉已要求的共鳴入口。

## Read-back

逐段講得出它新增甚麼；檢查新重點之間有空白行。再讀主帖末段接 reply，確保身份、語氣、閱讀理由同目的地一致。通過字數檢查只能證明長度符合，不能證明自然度或成效。
