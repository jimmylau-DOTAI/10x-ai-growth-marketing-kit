# Source discovery and content judgment

## 每日內容靈感袋

用品牌已確認客群、內容方向同客人常用字搵相關帖。按工作台時區計每日批次，預設香港時間、向執行時刻回望 24 小時。只收原發佈時間符合、讚數明確大於 100 嘅帖；數字被約整至無法判斷就留待核實。先按平台加原帖 ID 去重，無 ID 用同平台原帖連結。同一天最多收 5 篇，重試先讀當日已收嘅卡；合格少過五篇就交實數。

**點揀互動較高嘅帖。** 先計同平台、同格式、同一窗口同數據口徑嘅候選。有齊可比數據，就用（讚＋留言＋收藏＋分享）除以曝光；同組只提供播放量就用播放作分母，寫清口徑及觀察時間。平台少一類互動時，只用同組都有嘅項目，列出分子。不混排不同口徑；缺分母、分母為零或數據不可比就標「互動率未知」。優先有可比率嘅相關帖；仍有空位先用同組可見收藏、留言、分享量作後備，標示係按數量入選。缺數唔當零，候選名單只代表查到嘅範圍。

**Notion 一篇一張卡。** 新帖寫入原行銷參考庫，填標題、平台、原帖連結、Note ID、記錄日期同互動數據；正文補原發佈時間、搜尋詞、數據口徑及一句值得留意嘅原因。新卡將「選題決定」設為「待選」，喺「內容靈感袋」檢視見到。重遇舊帖只更新原卡快照，保留最初收集日期、人手決定、Source Guide 同關聯任務。

**提醒一次，等人揀。** 交當日編號、Notion 卡連結同入選原因，收尾問「想拆邊篇？可以覆編號，或者今日唔拆。」沿用當日批次同編號；重試唔重發提醒。無合格新帖只報數量或存取問題。未回覆或「今日唔拆」保留待選，可日後再揀。執行每日排程須由用戶啟用及設定時間；單次試跑只處理一次。

**揀中先拆。** 用戶揀邊張就將嗰張標「已選」，按原帖實際內容寫入同一張卡：原帖點開場、點用證據、讀者可以做咩、我方可以換入咩案例。重新打開卡片核對 Source Guide。資料足以完成用戶揀嘅拆解，先將選題決定改為「已拆解」，經「爆款拆解庫」檢視開返原卡。只睇到預覽或中斷時保留「已選」，記低仲欠咩。已有完整拆解就直接引用；另開製作任務時連返同一張卡。下次按品牌、題目或原帖搵舊拆解，以 Notion 卡正文為準。

## 一般來源研究

1. 先記話題、受眾、平台、期間與觀察時間。最近三日預設rolling 72h並記timezone；只有相對日期就如實寫精度，不能捏造精確timestamp。
2. TikHub 被指定時，查當前環境是否真有connector／已設定存取方法；先核對官方endpoint/schema。沒有工具／credential，只報缺口並問已設定位置，不要求把key貼進聊天，也不自行安裝或購買。可平行查公開原頁，但要明確記 browser fallback，不宣稱call過API。
3. 篩選期間要真正符合要求。如果API／UI只有一周，要逐篇核對三日內日期，不能把一周當三日。保存搜尋範圍、候選日期、互動量與擷取時間；API keys／xsec tokens不放receipt。
4. 爆款沒有通用門檻：用可見互動及同次候選範圍選高互動candidate，講明數字可能rounded；不聲稱全平台第一、成功原因或轉化。只有高讚但過期的內容不得勝出近期任務。
5. 原頁／媒體要真正檢查，按evidence capture標FULL/PARTIAL。AI故事、個人意見、高互動不等於事實。涉及健康等主張另外核對可信資料；沒有支持就刪掉或改成未知。
6. 寫一句內容判斷：受眾卡在哪裡 → 來源呈現甚麼張力 → 我們的新觀點 → 有甚麼證據 → 讀者可做甚麼。選一個最有用角度交carousel／post Skill；不要求初學者先填persona表。
7. Style reference與內容source分開：前者提供視覺機制，後者提供話題／觀察。不能抄作者身份、原句、虛構經驗或把原圖健康建議當品牌facts。

最小交接：Source receipt + audience + one message + creator judgment + claim boundary + CTA + requested count／dimensions + Style pointer。已有明確全流程本地示範授權就保留demo scope，不能自填成Human Approved。

官方查證例：2026-09-05核對 https://docs.tikhub.io/420136398e0 的 search_notes，列出一天／一周／半年而無三日選項。此例不是永久API契約；真正調用前仍讀當前schema。
