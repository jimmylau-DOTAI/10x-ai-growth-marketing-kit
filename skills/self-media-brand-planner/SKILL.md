# 自媒體品牌定位｜Jimmy Lau

先幫品牌答清楚兩條問題：「客人點解揀你？」同「就算今日唔買，佢點解下星期仲會返嚟睇？」品牌負責人揀定之後，將答案存返公司知識庫。公司、受眾同產品資料跨平台共用，個別帳號可以有自己嘅目的同語氣。

## 由用戶手上已有嘅資料開始

1. **認返品牌。** 先讀品牌首頁、公司介紹、產品或服務證據，再讀現有定位、品牌語氣同認可作品。見到已確認定位，交原句同來源；只改用戶今次提出嘅部分。從零開始亦可以用一個真實案例加一條客人問題起步。
2. **揀主要讀者。** 搵出客人喺咩情況、面對咩選擇、擔心咩，以及品牌憑咩幫得到佢。分清使用者同付款人。實際查詢可引原話，推演嘅情景標「待驗」。只問痛點就留喺呢一步。詳細做法見[客群分析](references/brand-audience-analysis.md)同[四類痛點](references/positioning-options.md)。
3. **提出三個值得追蹤嘅方向。** 用[實用、資訊、情緒、決策四種價值](references/marketing-judgment.md)搵出不同追蹤理由，按[三案十欄](references/positioning-options.md)交比較、各自嘅品牌證據同一個推薦理由。用戶想做完整價值練習，每種展開十題。想參考同行，先問有冇心水帳號或作品，再對照自家材料。未指定平台就做品牌共用定位。
4. **試清楚有冇嘢持續講。** 用戶揀定或要驗證一個方向，就按讀者需要建議內容主題，每個試列十個具體題目，用普通說話叫得出主題就夠。逐題辨認要用嘅來源；換產品名先湊夠十題，就收窄或合併。試題留作驗證，安排日期同寫稿等用戶提出。
5. **確認同保存。** 展示擬保存嘅定位同選擇理由。建議同定案分開；只有負責人明確揀定先記「已確認」。沿[保存方法](references/brand-library.md)喺用戶指定品牌知識庫原位更新，再打開同一頁核實，交返直達連結或檔案路徑。用戶只要定位，交到呢度。

## 保存一份下次搵得返嘅定案

已有 Notion 就喺「品牌內容平台」嘅「自媒體定位定案」一節寫入。有本機知識庫就更新原定位文件；未有正本，可在品牌資料夾建立「自媒體定位定案.md」，從品牌首頁加一條連結。每個品牌只用一份共用正本；相同選擇再次保存就更新原節。下面欄位直接用，按已有資料填。

| 欄位 | 寫低咩 |
| --- | --- |
| 品牌、適用範圍 | 公司或指定平台及帳號，連返公司介紹、受眾同風格原頁 |
| 主要讀者同處境 | 今期幫邊個、佢正作咩決定、最在意邊樣 |
| 定位同追蹤理由 | 一句講品牌憑咩幫到佢；一句講讀者下次點解返嚟 |
| 選擇同依據 | 揀邊個方向、原因、支持案例同來源；未核實嘅說法另標待驗 |
| 可持續內容主題 | 已揀主題、代表試題或題目清單連結；未試嘅留待驗 |
| 確認紀錄 | 草稿或已確認、確認人、日期；修訂時記改咗咩同原因 |

未有寫入權限，交可貼入原頁嘅內容並標「待保存」。下次開新對話，從品牌首頁連返最新已確認版本。若有較新草稿，講清楚邊份仍生效。

## 用戶要求製作時

讀返定位定案，將主要讀者、今次想幫佢做嘅決定、可用案例、品牌語氣同正本連結交畀寫手。按已安裝嘅 Skill 揀：搵參考用 `social-content-research`，社交文案用 `social-post-writing`，香港 Threads 用 `hk-threads-writer`，輪播用 `instagram-carousel-studio`。製作工具未裝，仍可交齊上述資料畀人接手。只做 IG 首頁或 Bio，直接讀[平台定位指引](references/positioning-options.md)。
