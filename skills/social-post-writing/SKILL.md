# Social Post Writing

## Overview

將一個可靠觀點寫成平台原生內容，而唔係將同一段文字貼去四個平台。核心原則：

> One Post, One Job, One Point.

工作流程：`Context → Job → Point → Shape → Write → Adapt → Check`。

## Required input

盡量取得：

- 已核實 Source、Idea 或 Campaign Handoff；
- Audience；
- Voice：Founder、Company 或 Neutral Expert；
- Post Job；
- Platform；
- Proof 或例子；
- CTA 及發布限制。

資料不足時只使用已知內容。CTA 未定就保留 `OPEN`，可另外建議選項，不要擅自製造優惠、Keyword Automation、活動資料或公司 Claim。

## Workflow

### 1. Set one job and one point

每篇 Post 只揀一個主要工作：

- Teach；
- Build trust；
- Start conversation；
- Announce；
- Drive action。

用一句寫出讀者睇完應記得嘅 Point。無法用一句講清楚時，先收窄題目。

### 2. Choose voice and shape

按 [post-shapes.md](references/post-shapes.md) 選擇 Teach、Opinion、Story、Announcement 或 Conversion。再決定：

- Founder：有第一身判斷、經驗及個人責任；
- Company：清楚組織角色、讀者價值及已核實事實；
- Neutral Expert：重點放方法與判斷，不冒充親身經歷。

不可為增加故事感而虛構失敗、客戶、對話或個人經驗。

### 3. Write the source version

先寫一個完整版本：

1. Hook；
2. Context 或 tension；
3. One Point；
4. Proof、example 或 practical implication；
5. CTA（只有在 Job 需要時）。

優先使用具體工作、例子及結果。避免新聞稿開場、資訊表、空泛 Hype、過多 Emoji 及無證據嘅絕對句。

### 4. Adapt by platform

如需要多平台版本，讀 [platform-adaptation.md](references/platform-adaptation.md)。保留同一 Point，但重新設計 Hook、節奏、Context、CTA 及長度。不要只改平台名稱或 Hashtag。

### 5. Check

使用 [quality-gate.md](references/quality-gate.md) 驗證事實、Voice、平台適配及 CTA。所有輸出保持 `DRAFT`，除非用戶另有已批准嘅發布流程。

## Output contract

先交一個簡短 Decision Header：

```text
Audience:
Voice:
Job:
One point:
Shape:
CTA: CONFIRMED | OPEN | NOT REQUIRED
```

之後輸出所需平台草稿。多平台 Pack 要補充：

- 每個版本嘅 Platform；
- Caption / Post；
- CTA；
- Assumptions；
- Fact or source notes；
- Status: `DRAFT`。

Decision Header、`OPEN`、Assumptions、Source Notes 及 Status 係內部交付欄位，不可混入可公開複製嘅 Post Body。CTA 未確認時，Post Body 留在自然結尾；將 CTA 候選放在草稿後面供用戶選擇。

需要完整 Brief 時使用 [post-brief.md](assets/post-brief.md)。

## Quality gate

- 第一段服務讀者，而非先交代公司背景；
- 一篇只有一個主要 Point；
- Founder、Company 及 Expert Voice 沒有混亂；
- 四個平台版本不是 Copy-paste；
- Claim、數字、合作、日期及 Offer 有來源；
- CTA 存在時與 Post Job 一致；
- 沒有自動公開、發送或假稱已發布。
