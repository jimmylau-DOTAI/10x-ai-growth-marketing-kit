# SEO + GEO Content

## Overview

建立既回答真實搜尋問題、亦容易被人同 AI 系統理解及引用嘅內容。核心流程係：`Intent → Type → Sources → Structure → Draft → Review`。

SEO 與 GEO 共用同一基礎：準確、具體、有來源、結構清楚。不要為迎合演算法而犧牲讀者價值。

## Required input

盡量取得：

- Primary query 或客戶問題；
- Audience、地區及語言；
- 文章目標及 Content Type；
- 公司、產品、服務或案例資料；
- 可用來源及內部連結；
- CTA、發布位置及審批人。

缺少資料時，先建立 Brief 或標示假設。不可虛構公司能力、客戶案例、價格、合作、結果或專家身份。

## Workflow

### 1. Define intent

確認搜尋者想了解、比較、決定、解決還是購買。選定一個 Primary Query、3–6 個 Related Questions 及文章完成後讀者應做到嘅下一步。

### 2. Select content type

按 [seo-geo-framework.md](references/seo-geo-framework.md) 選擇最合適嘅 Explainer、How-to、Comparison、Case、Service 或 News/Trend 結構。不要用同一種 Blog 模板處理所有查詢。

### 3. Build source and claim map

先讀用戶提供嘅 Sources；需要現況、法規、產品功能、數字或趨勢時，再查最新一手或權威來源。將 Claim 標示為：

- `VERIFIED`：已由可靠來源核實；
- `PROVIDED`：由用戶提供但未獨立核實；
- `INFERENCE`：根據證據作出嘅判斷；
- `SOURCE NEEDED`：不可公開使用。

搜尋結果摘要不是來源。推薦與引用要分開：品牌出現在列表不代表被來源支持。

### 4. Create structure

先用 [article-brief.md](assets/article-brief.md) 完成 Brief。文章要：

- 標題及開首直接符合 Search Intent；
- 重要問題先給簡短答案，再展開；
- 使用描述結果或決策嘅小標題；
- 提供步驟、例子、限制、取捨或決策準則；
- 讓每個主要段落可以獨立被理解。

### 5. Draft

使用清楚書面中文，按受眾加入自然香港語境。優先講工作、結果、流程及判斷，避免純工具 Feature List、空泛 AI Hype 及 Keyword Stuffing。

如果用戶要求「公司資料遲啲補」，可寫 Source-light Draft，但必須保留 `[COMPANY INPUT NEEDED]`、`[SOURCE NEEDED]`，不得製造完整可信假象。

### 6. Review

使用 [content-quality-check.md](references/content-quality-check.md) 及 [article-output.md](assets/article-output.md) 檢查 Intent、Claims、可讀性、可引用性、Meta、CTA、內部連結及狀態。

## Output contract

輸出包括：

1. Search Intent Brief；
2. Source and Claim Notes；
3. Outline；
4. Article Draft；
5. Meta Title and Description；
6. Suggested Internal Links；
7. QA Status and Open Items。

## Quality gate

- Primary Query 與文章答案一致；
- 每個時效性或高風險 Claim 有可追溯來源；
- 公司及案例內容來自已提供資料；
- 文章提供真正判斷或操作價值，而非重新包裝關鍵字；
- Heading、FAQ 及短答案自然，沒有為 GEO 大量堆砌；
- `READY FOR REVIEW` 不等於已發布。
